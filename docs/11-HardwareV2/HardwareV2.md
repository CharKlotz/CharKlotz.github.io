## Overview
If I could do the Human Machine Interface portion of our project over again, there are a few things i'd change about the overall design to make it easier to use. Overall, the subsystem worked as intended, so improvements are mainly going to be quality of life / nit-picky things.

## Bigger, Colored Display
The simple OLED display provided inside of class works well for the scope of the project, and I was able to make it work through the use of a coded in navigatable menu. However, it was very hard to get both a menu while also displaying information in from RX. Only having about 5 usable lines made it difficult to work with. If I could do it again, I would opt for a larger screen, and as an extra challenge allow for more than black and white displays. 

## Better Inputs
The final subsystem ended up using three different buttons to navigate the menu and control the whole system. They were used to navigate the OLED menu screen through an up, down, and select button. This was fine, but the buttons themselves had a few issues. They were small and hard to press in, so controlling the menu was a pain. Next time I would opt for larger buttons, or alternatively a different control scheme altogether. Originally I wanted to do a rotary encoder with a built in push switch, where you would still have the three controls up down and select, but instead it would be turning it left, right, and pushing it in. This ended up being way too hard, though if I spent more time on it I could definetely get it working right.

## USB - C
USB Micro B is way easier to connect and use than type C, since type C has way more extra connections that you have to keep in mind about. I avoided it for the project to make the final thing simpler, but it is a well documented process that would not be hard to learn how to do for next time. It would also make it more conveinent to connect to, since micro B cables are becomming rightfully rarer and rarer.
